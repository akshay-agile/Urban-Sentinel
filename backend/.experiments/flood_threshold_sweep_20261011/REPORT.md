# Flood threshold sweep — 2026-10-11

## Purpose and safety

This is an exploratory, still-image threshold comparison. It does not promote a threshold or alter production settings. No training, live endpoint, incident dispatch, database write, notification, model/config/dataset/label change, or package installation was performed. Production weights remain `Models/flood/runs/yolo11n_flood_waterlogging-3/weights/best.pt`; production threshold remains 0.65; mapping remains `{0: Flood, 1: Waterlogging}`.

## Inputs and provenance

- Source prediction file: `../flood_accuracy_audit_20261011/predictions.csv` (270 Flood-model image rows; predictions previously generated by the existing evaluator at the production setup).
- Fixed manifest: `manifest.csv`.
- 33 manually verified ordinary still photos under `D:\evaluation\ordinary_camera` plus 237 images from the Flood dataset test split. Of those test images, 2 have empty label files and 235 have nonempty Flood/Waterlogging labels. Thus 35 negative and 235 labeled-positive images are included.
- Positive labels are checked against the Flood dataset's class IDs 0=Flood and 1=Waterlogging. Empty labels only verify no annotation from those dataset classes. Ordinary photos were manually verified as ordinary scenes in the prior audit.
- The manifest marks source/session grouping as unknown. These are still images without session/location provenance. The original audit checked exact hashes and basenames across the Flood train/validation/test splits and found no exact overlaps, but near-duplicates or related recording scenes are not ruled out. The 33 ordinary images also appeared in earlier exploratory work. This set is not an independent threshold-selection set; results must remain exploratory.

## Method and reproducibility

The requested evaluator CLI/help and override were inspected. A fresh `evaluate_flood_temporal_replay.py` still-image inference attempt at 0.55 was started with the manifest below, but was stopped after over four minutes without producing inference outputs. Therefore this sweep uses saved raw model-returned boxes/confidences from the existing audit CSV and re-applies only the candidate confidence comparison offline. This holds the image set and saved inference predictions fixed across thresholds; it does not rerun the model and is not an independent replay result.

The saved CSV serializes confidence to six decimal places. At 0.65, re-derived qualifying prediction counts matched the saved production qualification counts for every image (0 mismatches). No saved prediction confidence equaled any of the five tested thresholds, so no exact boundary tie occurred at the available precision. Qualification is `confidence >= threshold`; classes remain Flood/Waterlogging. Per-image predictions preserve all saved model-returned detections, not only the strongest one. The output's family result is image presence: at least one qualifying Flood-family class on a labeled positive image, or any qualifying class on a verified negative image. Class metrics independently count class presence. Neither performs box IoU matching.

Exact commands, including the interrupted live-inference attempt and successful offline processing, are in `COMMANDS.md`. Every threshold has a separate output directory with `config.json`, `summary.json`, and `per_image_predictions.csv`; the scripts refuse to overwrite existing run output directories/files.

## Interpretation and recommendation

Lower thresholds reduce still-image misses but increase ordinary-image false alarms; raising thresholds moves the tradeoff in the other direction and sharply reduces Waterlogging recall in this sample. For example, 0.60 versus production 0.65 detects 9 more labeled-positive images and adds 1 negative-image false positive (20/35 vs 24/35 true negatives); 0.55 detects 15 more and adds 3 false positives. The 0.70 point removes 3 false positives versus 0.65 but misses 13 additional labeled-positive images. These are descriptive counts on a small, reused and source-unstratified set, not evidence for selecting a production operating point.

Recommendation: retain 0.65 in production and collect a fresh, session/location-separated validation set before choosing a threshold. Include ordinary indoor scenes and genuine Flood and Waterlogging scenes from representative cameras; group splits by recording session/location; reserve a test set untouched by threshold selection. Then run the same fixed weights and preprocessing at the candidate thresholds on validation and final test data. Still images cannot evaluate the three-consecutive-positive rule or incident-trigger behavior. Add ordered negative and hazard clips with event intervals before assessing false simulated triggers per clip/hour, missed events, detection delay, and per-class event recall. No conclusion about real-time or incident-level performance is supported here.

## Limitations

- No fresh model inference completed during this task; results are posthoc thresholding of saved predictions.
- The source evaluator's saved confidences are rounded to six decimal places.
- Image-level class presence is not box-matched precision/recall, mAP, or localization quality.
- No ordered video, temporal confirmation, incident, notification, frame/hour, or event-delay metric is evaluated.
- Source/session provenance for stills is unknown, and no near-duplicate/related-scene assessment was performed for the evaluation set.
- Flood dataset labels do not establish other hazard categories, though this evaluation concerns the Flood model/classes.
